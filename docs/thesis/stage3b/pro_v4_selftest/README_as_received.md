# Alpine Stage 3B Pro — Jev integration, v4.1 self-test

The named game file, **Alpine3B_PRO_v4.0_SELFTEST.html**, has been upgraded internally to **v4.1**. Its filename is retained for continuity. The standalone file runs with improved offline rules. This package adds a real TypeSafe/Jev API adapter for optional next-practice recommendations.

**Live Jev access was not available during preparation: no TypeSafe API key was configured.** Automated checks use clearly identified synthetic responses. They verify software behaviour, not Jev's decision quality or effects on human learning. Do not describe these changes as recommendations generated by Jev or as a completed Jev-versus-rules experiment.

## Open the game

- For offline self-testing, open `Alpine3B_PRO_v4.0_SELFTEST.html` in a browser that permits local HTML scripts. Some mobile file-preview apps do not run JavaScript; use a browser or the local server below.
- For Jev, use the included server on a computer. A downloaded HTML file alone cannot safely hold the API key or call the server. This package is not an internet-hosted service.

## Enable Jev on your computer

1. Use Node.js **22.9 or later**. No npm dependencies are required for the game or server.
2. Obtain an API key from your [TypeSafe dashboard](https://console.typesafe.ai/). Model access may depend on your account. Requests may incur TypeSafe charges.
3. In the unzipped folder, copy `.env.example` to `.env`, and replace the placeholder with your key **on your computer**. Do not put the key in the HTML, chat, a screenshot, an export, or a shared ZIP.
4. In a terminal in that folder, run:

   ```sh
   npm start
   ```

5. Open [http://127.0.0.1:8787](http://127.0.0.1:8787) on that computer. The status says whether Jev is configured. This does not assert that the key has been accepted by TypeSafe.
6. After a practice run, select **Ask Jev (TypeSafe) for this proposal**. Sending your current written comment is a separate option. Review the proposed activity, and choose whether to try it, change it, pause or finish.

To verify live connectivity with **synthetic data only**, run:

```sh
npm run check-jev
```

A successful call writes `live-check-result.json` with the actual returned model, choices, probabilities and applied local bounds. That check is not a human effectiveness test. An invalid key, unavailable model, timeout or service error leaves offline practice available.

The server binds to loopback and rejects other origins. It is deliberately not a public deployment. Opening the local URL on an iPad refers to the iPad itself, not your computer. A separate authenticated HTTPS deployment would be needed for remote devices.

## What changed

| Area | v4.1 behaviour |
|---|---|
| Mixed motivational evidence | Boredom/easiness with insufficient performance evidence can propose a different focus at the same pace, with a focus-specific visual cue. It does not automatically make the game easier. |
| Player feedback | Remains the player's own post-run report. Current selected feedback and prior selected feedback can inform the proposal. |
| Practice history | Retains the latest 12 practice observations, including stopped and interrupted runs. A stop is not automatically labelled abandonment. |
| Comparable observations | Descriptive clearance is grouped only at matching pace, guidance and input mode. Other observations stay visible to the decision engine with their settings. There is no invented difficulty-normalised mastery score. |
| Jev | Makes two independent typed judgments: next-practice action and a possible practice focus. It receives no participant code or profile. |
| Uncertainty | A deferred, weak, malformed or unavailable response leaves the offline proposal available. |
| Control | Code sets the numeric pace and duration. The player chooses whether to act. Fixed-course checks remain unchanged. |
| Reload | Reloading the feedback screen requires a fresh Jev opt-in. An edited report retains its previous version in the local audit. |
| Audit | Records the exact consented request, model result, confidence/probabilities, guard outcome, offline alternative, chosen action and the run to which it was applied. |

The five practice focuses have concrete effects when a visual cue is enabled: earlier obstacle attention, smaller turns, return towards the centre, safer coin choices, or clear-route choice. The cue is absent during fixed-course checks.

## Preserved design

The sequence remains warm-up, fixed-course self-check, practice, player feedback and a player-controlled next step. The optional closing check and original six questions remain. The inspected Pro build's game-over configuration and assessment course generator are retained; this is not a conversion of the earlier frozen study or zero-failure protocol.

This remains a **researcher self-test** with the existing participant-release restriction. The v4.1 browser namespace is separate from v4.0 so different policies are not silently pooled. Where prior v4.0 records exist in the same browser origin, Research tools provides **Export earlier v4.0 browser records**. Records stored under a different browser or file origin cannot be recovered by a participant code.

## Decision details

- Pace range: 0.40–2.20. Proposed increases are +0.10 and decreases −0.12; existing speed and density handling remains.
- A harder proposal needs the player's indication of interest in more challenge, at least six observed obstacles, at least 80% clearance, known edge time under 50%, and no conflicting tiredness/clarity/demand report. When enough matching observations exist, their clearance also informs the bound.
- Matching observations use pace within 0.01, the same guidance and input mode, and a stable pace within the run. This is an engineering grouping, not proof that the randomly generated courses are psychometrically equivalent.
- Jev action-confidence floor: 0.55. A harder Jev action additionally needs an action probability of at least 0.80. Focus-confidence floor: 0.45; below that the local focus is retained.
- These are **provisional engineering thresholds**, not calibrated thresholds validated for these learners. A Jev confidence value is not a learner's confidence, mastery probability, or predicted learning benefit.
- The client waits up to seven seconds; the adapter requests a five-second provider deadline. The player can finish while waiting. Late responses cannot start a run or change a finished session.
- No automatic retries are made during a practice decision. Offline behaviour is immediate after an error; a later explicit request can try again.

## Data sent and kept

By default, nothing is sent for inference. With the per-run Jev option, TypeSafe receives a short, whitelisted history of performance counts, game settings, completion categories and selected feedback. Only the current comment is sent, and only with its additional option. Previous comments, participant identifiers, age, profile, contact information and raw timestamps are excluded from the model request. Do not enter identifying or health information in a comment.

The browser retains the full research audit locally, including any consented comment in a request snapshot. CSV and JSON export remain manual. The server does not write player requests to disk or log their contents. The TypeSafe key remains in the server environment; static file serving is limited to the game. The provider's own terms and processing arrangements still apply to opted-in API calls.

## Files and checks

- `Alpine3B_PRO_v4.0_SELFTEST.html`: upgraded standalone game.
- `policy.cjs`: shared rules, history representation and local bounds.
- `jev.mjs`: request construction, typed-response validation and API adapter.
- `server.mjs`: local server; reads `TYPESAFE_API_KEY` and optional `JEV_MODEL`/`ALPINE_PORT`.
- `scripts/check-jev.mjs`: live connectivity check using synthetic experience data.
- `tests/core.test.mjs`: policy, privacy, response-contract and server checks.
- `tests/session.test.mjs` and `tests/session-harness.mjs`: execute the actual game script with minimal DOM/canvas stubs and synthetic network responses; these are not visual browser tests.
- `VALIDATION.md`: what was actually checked and what remains unverified.

Run `npm test` for the dependency-free core and isolated session checks. After changing `policy.cjs`, run `npm run sync-policy` to update the inline copy in the HTML, then rerun the checks. The tests require both policy copies to match. Visual layout, real browser input and a live Jev response still need checking on the intended device.

The model alias defaults to `jev-latest`; exports retain the model name actually returned by TypeSafe. For a controlled study, use a supported pinned model version if TypeSafe makes one available, and freeze the questions and local policy alongside it.

## API sources

Integration follows the [TypeSafe HTTP API](https://docs.typesafe.ai/api), [Choice contract](https://docs.typesafe.ai/primitives/choice), [confidence guidance](https://docs.typesafe.ai/confidence), and [quick start](https://docs.typesafe.ai/introduction/quickstart), checked 19 September 2026. There are no invented RLCD training routines in this package; it calls an existing Jev model and does not train its weights.
